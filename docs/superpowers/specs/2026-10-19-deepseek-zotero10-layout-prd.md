# Deepseek Copliot 新版开发 PRD

更新：2026-10-19｜文档版本：1.1（最小升级范围）  
状态：需求已收敛，尚未实施。目标版本沿用 1.1.0 计划，当前源码 package.json 为 1.0.1。  
本文件是本轮唯一生效 PRD；取代此前关于多搜索服务管理、复杂配置迁移和引用系统改造的设计。

## 1. 本版目标

用户更新插件后，旧对话和已有配置继续可用；插件使用新的 DeepSeek 模型，点击现有联网按钮即可直接搜索，无需配置联网 MCP、额外搜索 Key 或新服务。

本版只做：

1. 正常升级，保留历史和配置。
2. 移除 Pro 调用，统一 Flash，轻度/深度对应 low/max。
3. 在现有插件服务层直接接入 DeepSeek Search。
4. 完成 Zotero 10 的实际兼容检查，修复复现出的会话拥挤问题。

这里的“后端”指插件现有的模型访问、搜索和聊天编排代码，不新建独立服务器、代理网关或 MCP 服务。

## 2. 升级与数据保留——首要验收

- 保持现有插件 ID、偏好前缀、历史存储位置和记录格式，不通过卸载、清空数据或新建资料库完成升级。
- 更新后仍能打开、继续和导出旧对话；保留其文献归属、消息内容、标题和时间。
- 已有 DeepSeek Key、自定义命令、快捷键和联网开关等有效设置继续保留，不要求用户重新填写。
- 旧模型配置做必要兼容：Flash → 新 Flash + low；Pro → 新 Flash + max，保留原深度偏好。已有新版思考档位不在下次启动时被覆盖。
- 新安装默认轻度、思考开启、联网关闭；升级安装不重置用户的已有有效偏好。
- 旧 OpenAlex/Tavily/MCP 名称相关的设置值和 Key 可以留在原存储中，不删除用户数据；新版实际联网入口统一调用 DeepSeek，不再由这些旧字段选择服务。
- 更新说明用一句话交代“联网搜索现使用 DeepSeek，复用现有 API Key”。无需用户配置搜索服务。

实现以现有设置读取兼容、必要默认值补齐为主，不增加通用迁移框架、配置备份系统、回滚控制台或历史数据库重构。保留旧配置数据与继续运行旧模型/搜索服务是两件事：旧记录保留，运行路径按本版规则更新。

## 3. 模型访问与现有按钮

统一调用 `deepseek-flash`，移除前后台 Pro 可选项、调用和回退。历史消息中的 Pro 名称及旧值识别逻辑可保留，用于读取旧记录。

| 模式 | thinking.type | reasoning_effort | 联网按钮未选中 | 联网按钮选中 |
| --- | --- | --- | --- | --- |
| 轻度 | enabled | low | 直接回答，不搜索 | 搜索后回答 |
| 深度 | enabled | max | 直接回答，不搜索 | 搜索后回答 |

思考档位使用独立设置，不再靠切换模型 ID 实现。沿用 Chat Completions、流式输出、推理内容展示和既有上下文压缩；辅助压缩使用 Flash/low，用户档位决定最终回答力度。请求字段依据官方思考文档。[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)

联网沿用现有持久开关：选中即启用，取消即停用，不增加每会话/每条消息重置规则。发送时读取并固定本轮模式、联网状态和文献/会话；处理中切换设置只影响下一轮。Reader 自动生成入口与手动发送遵循同一规则。

保留现有错误展示和停止操作。服务端拒绝请求时提示错误，不静默回退 Pro；输出截断或只有推理没有正文时不能显示成功完成。

## 4. 联网搜索的最小实现

### 4.1 直接调用官方 API

联网按钮选中后，由现有 `evidenceSearch` 路径直接请求：

- `POST https://api.deepseek.com/v1/tools/search`
- 复用已有 DeepSeek API Key，以 Bearer 鉴权。
- 请求使用 `query`、`count: 5`、`need_content: true`。
- 接收结果的标题、URL、摘要及已返回正文，再交给现有聊天生成流程。[官方 Search 指南](https://api-docs.deepseek.com/zh-cn/guides/search/)

用户不需要配置 MCP 地址、启动 MCP 服务、安装额外工具或填写 Tavily Key。设置界面移除不再使用的搜索供应商/MCP 配置入口；不再扩建供应商选择器，也不自动回退 OpenAlex/Tavily。

### 4.2 最小处理规则

- 未选中联网按钮：不发任何搜索请求；模型不能自行启用联网。
- 选中后发送：执行一轮搜索，即使问题是翻译或改写也遵从按钮状态；low/max 不改变搜索轮数。
- 查询由当前问题和必要的文献标题/选区构造，不能发送整份论文或全部对话。官方要求 query 为 1–128 个 Unicode 字符，应做空值和长度检查；不新增模型查询规划器。[Search 请求约束](https://api-docs.deepseek.com/zh-cn/api/search/)
- 每轮搜索一次，最多取 5 条；优先使用已返回正文，否则使用摘要并如实说明。不单独开发 Fetch 抓取、递归网页阅读或多轮深度检索。
- 沿用现有网络超时处理，初始按 10 秒限制单次搜索，覆盖响应读取；本版不新增自动重试队列。
- 搜索结果按现有证据格式加入上下文。来源标题和链接随回答正文保存、显示与导出；可在正文末尾追加本轮实际结果列表，不新增来源数据库、引用解析引擎或逐句核验系统。
- 只把实际返回的网页列为搜索来源，不把模型编造的链接当作本轮搜索结果；仅有摘要时不宣称读过全文。网页文本是资料，不作为插件指令。
- 搜索无结果或失败时，在现有界面明确显示该状态；沿用当前文献回答路径时标明“本轮未获得联网来源”，不能显示已联网核实。若 Key 等配置缺失，走现有配置错误提示。
- 用户停止时，取消信号传入搜索和生成；阻止继续发起后续请求，并丢弃迟到回调。沿用现有会话停止与部分回答保存方式，不让旧请求写入新会话。

## 5. Zotero 10 与页面拥挤修复

这部分保留为必要兼容和缺陷修复，不扩大为界面重做。

- 在 Zotero 10 稳定版实测安装升级、文献文本读取、Library/Reader 聊天入口和历史恢复；对现有 Zotero 9 主路径做回归。当前 manifest 已声明 7.0–10.*，不把已有声明当作实测通过，也不无意降低原有兼容范围。
- 只修复实际命中的 API 兼容问题；重点检查当前使用的 PDFWorker.getFullText、FullText.getItemCacheFile、getSelectedItems 和原生侧栏挂载。
- 截图属于“最近会话”卡片，源码已有独立时间行。先复现标题、摘要、时间和按钮拥挤的位置，再做局部布局修复；聊天正文另行复现，不凭截图推断同一根因。
- Library/Reader 拖宽拖窄时，文字不覆盖或越界，按钮和输入可达；代码/公式/表格在自身区域内处理宽内容；不出现空白、闪烁、阅读位置乱跳或 PDF 会话串用。
- 保留宿主 auto-height 与现有宽度约束，不重新套用此前导致闪烁、已撤回的祖先宽度回写方案。
- 无法复现就记录已测环境和“未复现”，不盲改 CSS，也不宣称修复完成；模型与搜索开发可以继续推进。

兼容依据：[Zotero 10 开发者说明](https://www.zotero.org/support/dev/zotero_10_for_developers)。实际测试记录宿主准确版本，实测通过后同步必要的兼容声明和更新说明。

## 6. 开发顺序与代码边界

沿用现有项目结构，按以下顺序推进，不新增架构层：

| 顺序 | 必要工作 | 主要代码范围 |
| --- | --- | --- |
| 1 | 旧配置兼容、独立思考档位、Flash 请求参数、移除 Pro | settingsManager、provider/types、openAICompatibleProvider、chatEngine、Composer/Sidebar |
| 2 | 用 DeepSeek 替换联网执行路径，复用 Key；简化设置入口，接入取消和来源列表 | evidenceSearch、chatEngine、现有会话请求链、preferences 与文案 |
| 3 | Zotero 10 兼容核验和已复现布局修复 | contextAssembler、scopeResolver、ui/sidebarSection、Sidebar、ThreadView |
| 4 | 构建新 XPI，原生覆盖升级并验证历史/配置保留 | 现有构建、manifest 与更新说明 |

历史存储和会话结构原则上不改。只有现有接口无法表达必要行为时，才做局部字段扩展，不为本版重写服务、存储或 UI。

源码审查基线为 c8162b5；实施前检查当前 HEAD 和未提交改动。仓库 progress.md 与 docs/debug/2026-09-28-sidebar-clipping/ 里的闪烁撤回记录需要继承。

## 7. 最小验收清单

1. **覆盖升级**：使用含旧会话、Key、自定义命令、快捷键和偏好的测试配置安装新版 XPI，重启后旧对话可打开、继续、导出，配置无需重填；再次启动不会重置。
2. **模型四组合**：轻度/深度 × 联网开/关，实际请求均使用 Flash，档位正确，无 Pro 请求；联网关闭时无搜索请求。
3. **无需 MCP**：在未配置/未启动任何 MCP、没有 Tavily Key 的环境，只使用已有 DeepSeek Key，点击联网后能搜到结果并回答，来源可打开；旧搜索设置不能把请求导向旧服务。
4. **异常与停止**：搜索无结果、超时、错误都有明确状态；搜索中和生成中停止后不继续请求，也不污染下一轮。
5. **宿主与布局**：真实 Zotero 10 的 Library/Reader 可用；用长标题和长回答检查约 350/280/260 px 及宽→窄→宽，检查一次放大字体和 PDF A→B→A；无覆盖、裁切、闪烁、输入不可达或串会话。宿主宽度达不到目标时记录实际宽度。
6. **升级产物一致**：确认原生插件管理器中安装的版本属于本次构建，重启后再验收；兼容声明、XPI 和更新元数据一致。

对本次改动先跑聚焦测试，再按仓库要求运行必要项目检查、构建和真实 XPI 验收。至少一次旧版覆盖升级与一次无 MCP 的真实搜索必须验证，不能以文档、mock 或旧包截图替代。真实调用使用合成问题，不为布局测试上传论文。

扩展平台/缩放组合沿用项目现有发布检查，不新建一套庞大矩阵。没有测试的环境如实记录，不能写成全部兼容已通过。

## 8. 本版明确不做

- 视觉模型、截图问 AI。
- MCP 接入或部署、独立后端服务、通用供应商/网关架构。
- 多搜索服务管理、自动服务切换、Fetch 抓取和多轮研究。
- 来源数据库、复杂引用渲染、证据缓存系统。
- 通用迁移/备份/回滚系统、历史记录格式重构。
- 全面 UI 重设计及没有复现依据的宿主修补。

本稿已按用户“避免过度开发”的要求收紧。接下来实施服务层模型访问与联网功能时，以本稿为准；本轮仅更新 PRD，尚未修改产品代码或发布插件。
